# Gestão de Usuários, Helpdesk e Launcher Ogum Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recomendado) ou `superpowers:executing-plans`. Steps usam `- [ ]`.

**Goal:** Entregar módulo admin-only de gestão de usuários, painel USER-only de relato de problemas, helpdesk administrativo e launcher flutuante Ogum no canto inferior direito com ações por role.

**Architecture:** API Spring Boot mantém autorização por URL em `SecurityConfig` e isolamento por `empresa_id` + `usuario_id`; helpdesk ganha migration V12, entidades, serviço e controllers USER/ADMIN. Web Next.js 16 consome via Server Components/actions e BFF allowlist; nav e launcher derivam da role do `/api/auth/me`.

**Tech Stack:** Java 21, Spring Boot 3, Spring Security/JWT, JPA, Flyway, PostgreSQL, JUnit/Mockito/ArchUnit/Testcontainers; Next.js 16 App Router, TypeScript, Tailwind v4, Playwright.

**Spec:** `AGENTS.md` + decisões confirmadas na conversa: API + Web + BFF, soft delete de usuário, launcher direita com menu, branch atual.

**Status:** executado a partir de `6f9892c`; RAG já está comitado nesse HEAD e não é trabalho sujo. Branch criada: `feat/gestao-usuarios-helpdesk-ogum`.

## Global Constraints

- Branch: `feat/gestao-usuarios-helpdesk-ogum`, criada a partir de `6f9892c`.
- O commit `6f9892c` já contém RAG, ferramentas, V11 e matcher `/api/ai/rag/**`; não remover nem reescrever esse trabalho. Ao editar `SecurityConfig`, preservar o matcher RAG existente.
- TDD obrigatório por tarefa: teste falhando → código mínimo → teste passando → commit.
- `empresa_id` vem exclusivamente do JWT (`TenantContext`); nenhum request aceita `empresaId`/`usuarioId` no body. USER vê apenas seus próprios tickets; ADMIN vê a fila da empresa.
- Não introduzir `@PreAuthorize`; padrão atual é `requestMatchers(...).hasRole(...)` em `SecurityConfig`.
- Exclusão de usuário = soft delete: reutilizar `desativar`, manter FKs e incrementar `tokenVersion`. Hard delete fora de escopo.
- Usar nomes em português, nenhum `double`/`float` para dinheiro, DTOs `record`.
- Next 16: ler `web/node_modules/next/dist/docs/` antes de editar rotas, `cookies()` ou layout.
- UI: `/ogum.svg` já existe; launcher vai para `bottom-right`, com alvos ≥44px, `aria-expanded`, foco visível, `reduced-motion`, sem colisão com Sheet mobile nem barra de importação; sem violeta/lavanda.
- Gates:
  - `api`: `.\mvnw.cmd "-Dspotless.check.skip=true" test` e `.\mvnw.cmd -q spotless:check`
  - `web`: `npm run lint`, `npx tsc --noEmit`, `npx playwright test e2e/frontend-fixes.spec.ts e2e/google-oauth.spec.ts e2e/auth-bff.spec.ts e2e/user-helpdesk.spec.ts`, `npm run build`
  - Docker opcional: `.\mvnw.cmd test "-Dsurefire.excludes="`
- Artefato GSD: este arquivo; summary em `.planning/quick/261124-gestao-usuarios-helpdesk/261124-SUMMARY.md`.

## Review Focus

- Role bypass: ADMIN em `/api/helpdesk/**` e USER em `/api/admin/**` devem receber 403 — Task 2.
- Enumeração cross-tenant/cross-user: ID de outro usuário ou empresa retorna 404 — Task 2.
- Último ADMIN ativo e auto-demotição/exclusão: sempre 409 — Task 3.
- JWT obsoleto após mudança de role/desativação: `tokenVersion` invalida sessão antiga — Task 3.
- Launcher: direita, teclado, foco, 390px e mobile Sheet sem sobreposição — Task 9.
