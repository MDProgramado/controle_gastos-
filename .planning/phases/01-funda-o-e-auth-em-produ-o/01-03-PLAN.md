`login/route.ts` (POST): lê o JSON do body e faz `fetch` para `${process.env.API_URL}/api/auth/login`. Se a API responder 401 → retorna 401 `{"erro": "E-mail ou senha inválidos"}` (mensagem genérica do UI-SPEC — D-05); 5xx/erro de rede → 502 `{"erro": "Não foi possível conectar. `logout/route.ts` (POST): `cookieStore.delete('sess')` → `{ ok: true }`.

`me/route.ts` (GET): lê o cookie; sem cookie → 401 ProblemDetail-shape `{"erro": "não autenticado"}`; com cookie → forward para `${API_URL}/api/auth/me` com header `Authorization: Bearer <cookie>` e repassa status/body (401 da API → limpa cookie antes de responder — prepara o fluxo de sessão expirada).

`lib/api.ts`: helper server-side `getMe()` usável por Server Components (lê cookie, chama `me/route` interno ou a API direto com Bearer — escolha uma e documente no SUMMARY). `API_URL` é server-only.

Proibições (grep-gates): nenhum `localStorage`/`sessionStorage`; nenhum `NEXT_PUBLIC_` para `API_URL` ou token; nenhum `cookies()` síncrono.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser→BFF (rota login) | senha do usuário atravessa o form — o browser nunca vê o JWT depois do set do cookie |
| BFF→API | `API_URL` server-side; forward com Bearer lido do cookie |
| Rota protegida→proxy | presença de cookie decide acesso — cookie é o gate (o JWT continua sendo validado na API) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-01 | Information Disclosure | Token roubado via XSS | mitigate | Cookie `httpOnly` + BFF (D-02): JWT fora do alcance de JS; grep-gate `localStorage`/`sessionStorage` → 0 |
| T-3-02 | Spoofing | Forja de sessão | mitigate | API valida assinatura/`exp` de todo Bearer (plano 02); o BFF não confia no cookie sem repassar à API |
| T-3-03 | CSRF | Cookie enviado automaticamente same-site | mitigate | `SameSite=Lax` + API aceita SÓ Bearer (dupla barreira, Pitfall 10); nunca `SameSite=None` |
| T-3-04 | Information Disclosure | `API_URL`/token no bundle do cliente | mitigate | Env `API_URL` server-only; grep-gate `NEXT_PUBLIC_` → 0 (anti-pattern 3) |
| T-3-05 | Information Disclosure | Enumeração de credenciais na UI | mitigate | Copys genéricas obrigatórias (D-05/UI-SPEC): mesma mensagem p/ e-mail inexistente e senha errada |
| T-3-06 | Tampering | Cookie sem `Secure` em produção | mitigate | `secure: NODE_ENV === 'production'` (AUTH-06 — verificado no plano 04 via HTTPS) |
| T-3-SC | Tampering | shadcn/lucide-react (npm) | mitigate | Registros: apenas shadcn oficial — UI-SPEC "Registry Safety" not required; zero third-party registries |
</threat_model>
