<D-08-decision>
## D-08 — DECIDIDO: banco Postgres SEPARADO para staging (2ª instância no Render)

**Escolha:** staging recebe o próprio Postgres (instância dedicada, pago) + o próprio serviço web da API — espelhando produção.

**Rationale (dados de custo do RESEARCH Open Questions 1):**
1. **Custo × segurança:** +US$13–25/mês aceitáveis frente ao risco de um deploy de teste tocar dados reais do cliente; orçamento implícito no pedido do usuário ("staging pois penso em escalar").
2. **Isolamento por construção:** env vars (`SEED_ADMIN_PASSWORD`, `JWT_SECRET`) são por serviço — banco único compartilhado misturaria seeds/sessões e exporia dados reais a deploys de preview (Vercel preview → staging é exatamente o Pitfall 8).
3. **Escalabilidade (motivo original do D-06):** modelo "um serviço + um banco por ambiente" é o mesmo que replica para novos clientes/empresas depois — nenhum rework.
4. **Alternativa rejeitada:** banco único com "dados de teste" — a Render não oferece múltiplos databases isolados por instância de forma recomendada; limpar dados reais manualmente é operação frágil e humana.

**Registro:** decisão também gravada em `01-SKELETON.md` (contrato para fases seguintes).
</D-08-decision>
