## Spacing Scale

Declared values (must be multiples of 4) — escala padrão do Tailwind, sem desvios:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap entre label e input, gaps de ícone |
| sm | 8px | Gap entre campos do formulário |
| md | 16px | Padding de página no mobile, spacing padrão |
| lg | 24px | Padding vertical do card |
| xl | 32px | Padding do card (desktop), gaps de layout |
| 2xl | 48px | Respiro acima do bloco de marca |
| 3xl | 64px | Margem inferior do rodapé/credenciais |

Exceptions: **nenhuma**. Alvos de toque (inputs, botões) usam `min-height: 44px` (múltiplo de 4) em todo viewport.

## Typography

Fonte: system stack (Design System). Pesos declarados: **400 (regular) + 600 (semibold)** — exatamente dois.

| Role | Size | Weight | Line Height | Uso na fase |
|------|------|--------|-------------|-------------|
| Body | 16px | 400 | 1.5 | Texto de apoio, valores de input |
| Label | 14px | 600 | 1.4 | Labels de campo ("E-mail", "Senha"), texto de botão |
| Heading | 20px | 600 | 1.2 | Título do card / heading da página placeholder pós-login |
| Display | 28px | 600 | 1.2 | Nome da marca "Controle Financeiro" acima do card |

- Texto de erro/ajuda: 14px / 400 / 1.4, cor destructive/muted-foreground.
- Override shadcn: base font-size do app = **16px** (não o default 14px do shadcn) — `--text-base`/raiz em 16px.

## Color

Tema claro. 60% neutro claro · 30% cartões brancos · 10% acento verde financeiro. Valores em hex fixos, também declarados como tokens semânticos (CSS variables no padrão shadcn):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F8FAFC` (slate-50) | `--background`: fundo da página, superfície padrão |
| Secondary (30%) | `#FFFFFF` (branco) + borda `#E2E8F0` (slate-200) | `--card` / `--popover`: card de login, futuras tabelas e painéis |
| Accent (10%) | `#0F766E` (teal-700), hover `#115E59` (teal-800), foreground `#FFFFFF` | `--primary`: **somente** botão "Entrar", focus ring, estado ativo/selecionado e destaques de saldo positivo (fase 3) |
| Destructive | `#DC2626` (red-600), foreground `#FFFFFF` | `--destructive`: erro de credenciais, validação inválida, valores de SAÍDA (fase 2+) |
| Text primary | `#0F172A` (slate-900) | `--foreground`: texto principal |
| Text muted | `#64748B` (slate-500) | `--muted-foreground`: subtítulos, placeholders, apoio |

**Accent reserved for (lista explícita — nunca "todos os elementos interativos"):**
1. Botão primário "Entrar" (CTA de login)
2. Focus ring de todo elemento interativo
3. Indicadores de estado ativo/selecionado (futuro: mês selecionado, aba ativa)
4. Saldo positivo / destaque de número confiável (fase 3)

**Tokens semânticos de dinheiro (declarados agora, usados a partir da fase 2 — reuso obrigatório):**
- Entrada (saldo positivo): `#16A34A` (green-600)
- Saída (saldo negativo, valores de despesa): `#DC2626` (same destructive)
- Nenhum `double`/float na formatação — formatação monetária via `Intl.NumberFormat('pt-BR', { style: 'currency', currency: 'BRL' })` (regra do projeto: centavos confiáveis).

**Contraste (WCAG 2.1 AA):** `#0F766E` sobre texto branco ≈ 5.3:1 ✓; `#0F172A` sobre `#F8FAFC` ≈ 17:1 ✓; `#64748B` sobre `#FFFFFF` ≈ 4.8:1 ✓. Foco visível em todo interativo.

**Raio:** base `--radius: 8px` (0.5rem); inputs/botões `8px`; card `12px`; pill/full apenas para avatar futuro.

**Foco:** `outline: 2px solid #0F766E; outline-offset: 2px` em `:focus-visible` de todos os elementos interativos (teclado apenas; shadcn `--ring` = `#0F766E`).

## Copywriting Contract

Todo texto de UI em **pt-BR**. Mensagens de credencial são **genéricas** (D-05 — nunca revelar qual campo falhou / anti-enumeração).

| Element | Copy |
|---------|------|
| Marca (Display, acima do card) | `Controle Financeiro` |
| Subtítulo do login | `Entre com seu e-mail e senha.` |
| Label e-mail | `E-mail` (placeholder: `seu@email.com`) |
| Label senha | `Senha` (sem placeholder; `type="password"`, `autocomplete="current-password"`) |
| Primary CTA | `Entrar` (verbo de ação — único botão de submit; durante envio: `Entrando…` + spinner, `disabled`) |
| Empty state heading (não aplicável à tela de login — ver placeholder pós-login) | — |
| Empty state (placeholder pós-login, rota `/`) | Heading: `Você está autenticado.` · Body: `O dashboard chega na Fase 3. Use o botão Sair para encerrar a sessão.` |
| Error — credenciais inválidas (401) | `E-mail ou senha inválidos. Verifique os dados e tente novamente.` (mensagem única para e-mail inexistente OU senha errada) |
| Error — rede/servidor (5xx/network) | `Não foi possível conectar. Tente novamente em instantes.` |
| Error — validação e-mail | `Informe seu e-mail.` / `Informe um e-mail válido.` |
| Error — validação senha | `Informe sua senha.` |
| Sessão expirada (redirect com `?expirada=1`, JWT 8h sem refresh — D-01/D-02) | `Sua sessão expirou. Entre novamente.` (banner no topo do card, `role="status"`) |
| Botão logout (placeholder pós-login) | `Sair` (limpa cookie via `/api/auth/logout`; **sem** confirmação — não é destrutivo) |
| Destructive confirmation | Nenhuma nesta fase (nenhuma ação destrutiva de dados) |

Regras de exibição de erro:
- Erro de credencial aparece em `<Alert variant="destructive">` **abaixo** dos campos, `role="alert"`; nunca toast nesta fase.
- Ao 401: manter o valor do e-mail, **limpar o campo de senha** e devolver foco ao campo de senha.
- Erros de validação aparecem inline abaixo de cada campo, 14px destructive, vinculados via `aria-describedby`.

## Interaction Contract

| Interação | Comportamento |
|-----------|---------------|
| Submit | Enter implícito do form OU clique em "Entrar" — único caminho (sem extras: sem "lembrar-me", sem "esqueci a senha", sem social login — D-05) |
| Loading | Botão `disabled` + label `Entrando…` + spinner (`Loader2` animado, `aria-busy="true"`); inputs permanecem visíveis |
| Sucesso | BFF seta cookie httpOnly `sess` (8h) → redirect para `/` (shell protegido) |
| Falha 401 | Alert genérico (acima); e-mail mantido; senha limpa; foco no campo senha |
| Falha 5xx/rede | Alert "Não foi possível conectar…" (acima) |
| Rota protegida sem cookie | `proxy.ts` (Next 16) redireciona `/` → `/login` |
| Já autenticado em `/login` | Redirect `/` → `/login` não é aplicado ao inverso: autenticado acessando `/login` é redirecionado para `/` |
| Sessão expirada (401 em request autenticado) | BFF limpa cookie → redirect `/login?expirada=1` → banner `Sua sessão expirou. Entre novamente.` |
| Token na UI | **Nunca visível**: JWT vive só no cookie httpOnly gerido pelo BFF (D-02); nada de `localStorage` |

**Layout responsivo (desktop primeiro, mobile utilizável):**
- ≥768px: card centralizado vertical e horizontalmente, `max-width: 400px`, padding 32px, sombra sutil (`--shadow-md`), fundo `#F8FAFC`.
- <768px: card full-width com 16px de margem de página; inputs e botões `width: 100%`, `min-height: 44px`.
- Acima do card (ambos): marca em Display 28px semibold, subtítulo muted 16px.

**Acessibilidade (obrigatório):**
- `<html lang="pt-BR">` (configurar no `layout.tsx` root).
- Um único `h1` por página (marca "Controle Financeiro" no login).
- Labels associados (`<Label htmlFor>`), `type="email"` + `autocomplete="email"`, `autocomplete="current-password"`.
- `role="alert"` no alert de erro (anúncio automático), `role="status"` no banner de expiração.
- Focus ring visível via `:focus-visible` (teclado); navegação completa por teclado; Enter submete.
- Alvos de toque ≥ 44px.

**Estados da tela de login (inventário):** default · focus · invalid (client validation: borda destructive + mensagem inline) · submitting (spinner) · erro-credencial (alert) · erro-rede (alert) · sessão-expirada (banner + estado default) · sucesso (redirect).
