# 05-06 — Web: BFF multipart e página /importacoes (upload, revisão, confirmação)

**Wave:** 6 | **Depends on:** 05-04, 05-05 | **Autonomous:** true | **Frontmatter status:** complete

## Objective

Entregar a interface web de importação: BFF em Next.js (routes `web/app/api/importacoes/route.ts` e `web/app/api/importacoes/[id]/confirmar/route.ts`) que lê o cookie httpOnly `sess` e repassa `Authorization: Bearer` para a API (nunca expor a chave OpenRouter nem falar direto do browser); página `web/app/importacoes/page.tsx` (Server Component) + componentes cliente em `web/components/importacoes/` (dropzone multi-PDF, revisão item a item, KPIs do resumo, alertas, confirmação); navegação "Importar PDF" no `TopNav`/`sidebar`. Visual conforme `05-UI-SPEC.md` e `design-taste-frontend` (tokens de `web/app/globals.css`, shadcn/ui existentes).

## Requirements

IMP-01, IMP-03, IMP-09, IMP-10, IMP-15

## Decisions covered

D-03 (UI incluída), D-28 (BFF cookie→Bearer), D-29 (limite 4 MB/arquivo, 5 arquivos no BFF; mensagem clara), D-30 (checkbox por item + select de categoria com override), D-31 (visual design-taste-frontend, tokens do globals.css), D-32 (item "Importar PDF" na navegação)

## Threat Model

| Ameaça | Severidade | Mitigação |
|--------|------------|-----------|
| Chave OpenRouter exposta ao browser | Alta | BFF nunca envia chave; apenas repassa Bearer do cookie `sess` para a API (padrão `web/app/api/ai/chat/route.ts`) |
| Upload de arquivo > limite da Vercel (4,5 MB corpo) | Alta | BFF rejeita > 4 MB/arquivo e > 5 arquivos com 413 + mensagem clara em pt-BR (D-29) |
| XSS via descrição/categoria vinda da IA | Média | Renderizar descrição/categoria como texto (não `dangerouslySetInnerHTML`); escapar |
| IDOR: acessar importação de outra empresa | Alta | BFF repassa Bearer; API valida `empresa_id` do token em cada endpoint |
