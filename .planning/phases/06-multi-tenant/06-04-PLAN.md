# 06-04 — Isolamento por usuário em todo o sistema (Fase 3)

**Wave:** 4 | **Depends on:** 06-02 (paralelo a 06-03; executar depois dele sem worktrees) | **Autonomous:** true | **Fase:** F3

## Objective
Fazer valer a regra D-03/D-16: `empresa_id + usuario_id` em **toda** consulta financeira (lançamentos, importações, dashboard, contas a pagar, IA, WhatsApp), com `UsuarioContext`, invalidação imediata por `token_version`/`ativo`, role validada contra enum e ArchUnit impedindo regressão. ADMIN continua sem acesso a dados alheios.

## Requirements
AUTH-01, AUTH-03, AUTH-05, GROW-01 · **MT-03**

## Decisions covered
D-03 (isolamento por usuário, nem ADMIN vê dados alheios), D-04 (ADMIN só contas), D-11 (índices), D-12 (tenant só do JWT/contexto), D-13 (`UsuarioContext`, claim `usuario_id`, lookups por id), D-14 (`token_version`/`ativo` no filtro), D-15 (role enum), D-16 (matriz de isolamento), D-24 (aceite F3).

## Threat Model
| Ameaça | Severidade | Mitigação |
|--------|------------|-----------|
| IDOR cross-user / cross-tenant em endpoint financeiro | Alta | `findByIdAndEmpresaIdAndUsuarioId` em toda query; teste 404 (não 403, para não revelar existência) |
| ADMIN lendo dados de outros usuários | Alta | Mesmo filtro para ADMIN; teste explícito ADMIN→404/403 (D-23) |
| JWT de usuário demitido continua válido por 8h | Alta | Filtro valida `ativo` e `token_version` contra o banco a cada request |
| Role tampering (`ROLE_ROOT`) | Alta | Enum `Role` na conversão do JWT; qualquer outro valor → 401 |
| Histórico de IA cruzando entre usuários com mesmo `sessionId` | Alta | Chave `empresa_id::usuario_id::sessionId`; teste de não-cruzamento |
| Async WhatsApp sem `SecurityContext` | Média | Passar `empresaId`/`usuarioId` explicitamente, como já feito para tenant |

## Risk Notes
- **Filtro de `token_version`:** adiciona uma consulta por request (risco aceito em MULT_TENANT.md §9). Usar `@Transactional(readOnly=true)` ou cache curto se necessário, sem alterar semântica.
- **ADMIN→404 vs 403:** usar 404 para não revelar existência do recurso; o aceite D-24 admite 404/403, mas 404 é preferível.
- **V10:** o documento só nomeia V9; uma migration adicional é necessária para persistência de IA multi-replica (D-16/§9). Criar V10 seguindo a regra de imutabilidade.
- **Histórico legado:** permanece no ADMIN seed (D-17) — não migrar nesta fase.
