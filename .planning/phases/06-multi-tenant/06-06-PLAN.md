# 06-06 — Frontend: cadastro, convite, gestão e Google (Fase 5)

**Wave:** 6 | **Depends on:** 06-03, 06-04, 06-05 | **Autonomous:** true | **Fase:** F5

## Objective
Entregar as telas e os BFFs para os fluxos novos — cadastro self-service, aceite de convite, gestão de contas (ADMIN) e botão "Entrar com Google" — com role coerente com o backend, allowlist no `proxy.ts` e cobertura e2e no Playwright.

## Requirements
GROW-01, GROW-02, AUTH-01 · **MT-05**

## Decisions covered
D-02 (cadastro self-service), D-04 (ADMIN só gestão de contas), D-18 (contratos), D-19 (BFF repassa Bearer, cookie `sess`), D-24 (aceite F5: e2e + role UI coerente).

## Threat Model
| Ameaça | Severidade | Mitigação |
|--------|------------|-----------|
| Browser falando direto com a API (JWT exposto) | Alta | Todos os fluxos passam por BFF em `web/app/api/**`; cookie httpOnly |
| Usuário USER vendo ação de ADMIN na UI | Média | Sidebar/links condicionados ao role do `/api/me`; backend continua autoridade (403) |
| Token de convite em URL vazando por referrer/analytics | Média | Página `/convite/[token]` não envia o token a terceiros; BFF consome uma vez |
| XSS em nome/empresa vindos do cadastro | Média | Escaping padrão React; validação no BFF |
| Página pública redirecionada para `/login` pelo proxy | Média | Allowlist explícita em `web/proxy.ts` |
